# ポーズ・構図プロンプト工房

一人の人物について、身体各部の関係とカメラ構図を構造化し、矛盾・手の使用数・現在の画角で見える範囲を確認して、画像生成AI向けの英語プロンプトへ変換する静的Webアプリです。二人用ポーズ（人物A・Bの配置と接触点）と、PIXAI Tsubaki／PIXAI SDXL／NovelAI向けの出力にも対応しています。

旧ポーズビルダーの項目やタグ連結処理は移植していません。身体状態を保持する `state`、正規化、`advisor`、`generator`、UIを分離しています。

## 起動方法

`index.html` をブラウザで開いてください。ビルド、npm、外部サーバー、外部APIは不要です。`file://` と GitHub Pages のどちらでも基本機能が動作します。

自動テストは `tests.html` を開くと実行されます。現在のテスト数は634件です。

## 主な機能

- 二人用ポーズ7種（覆いかぶさる、背後から身を寄せる、向かい合ってまたがる、膝の上に向かい合って座る／背中を向けて座る、背後から抱き寄せる、片脚を上げて支える）。人物A（主導側）・B（相手側）の配置、上下・前後・向き、接触点、推奨カメラを表示
- 出力先の切り替え：汎用（従来の3形式）／PIXAI Tsubaki（自然文）／PIXAI SDXL（短いタグ）／NovelAI（共通＋Character Prompts）。切り替えても選択内容は保持
- PIXAI系では adult／bust を含む語を出力しない。強調構文はSDXL `(…:1.2)`、NovelAI `{{ }}` または `1.2:: ::` を必要時だけ使用
- NovelAI用の共通・人物A・人物Bの個別コピー、`|` 区切りの一括コピー
- 人物A・Bの外見・服装プロンプト欄。貼り付けた英語タグや文章を、選んだポーズと出力先別に自動で組み合わせる（人数タグの整理、強調構文の変換、性別の推定は画面で通知）
- 人物プロンプトセットの保存・読み込み（最大30件）、人物ごとのクリア、消える範囲を選べるリセット
- 一人用／二人用の切り替え、日本語でのポーズ検索（ひらがな・カタカナ・主な読みに対応）、ポーズと矛盾するカメラ・撮影範囲の無効化と理由表示
- 下部バーでの英語プロンプトのリアルタイムプレビューとワンタップコピー
- かんたん設計、プリセット開始、詳細設計の3入口
- 整合済みの開始地点として使えるビルトインプリセット77件（基本ポーズ15件、恋人・親しい相手46件、特殊・演出16件）
- 「すべて／基本ポーズ／恋人・親しい相手／特殊・演出」の用途カテゴリと動的件数表示
- 10種類のポーズ系統、撮影範囲、恋人カテゴリ専用の雰囲気・シーン・やりとりを組み合わせた絞り込み
- 「特殊ポーズ・運動」8件（土下座、両腕を上げるストレッチ、蹲踞、四股の構え、I字バランス、馬跳びの馬、前屈、ブリッジ）
- compact専用の標準タグ短縮と、主ポーズ／補助条件／安定化補助の3層化。詳細英文・日本語構造・自由入力は維持
- Viewerとの片手のやりとりを構造化した6プリセット（差し出す、手を引く、半分ハート、手の甲へ口づける、一口差し出す、頬へ添える）
- 英語プロンプトの撮影視点をviewer / viewpoint表現へ統一し、実物のカメラ機材として解釈されにくい語彙へ調整
- 姿勢、動作、雰囲気、重心、脚、骨盤、背面強調、上半身、肩の構造化
- 腕A・腕Bと、両腕を使う複合ポーズの分離
- 顔の向き、顎、首、視線対象、視線方向、目の状態、4群へ整理した単一選択の表情候補
- 一人だけを描いたまま、画面外の相手との距離・接近動作を表す相手視点設定
- ソファ、ベッド、仰向け・横向き・うつ伏せ、両手・両膝を明示する四点支持、膝立ち、前傾支持、背中主役、背面・振り返り、顔隠し、顔近くの愛情ジェスチャー
- 撮影範囲、カメラ高さ、傾き、人物配置、余白、奥行き、構図リズム
- hard / warning / info の設計アドバイザーとpatch形式の修正案
- 既存ポーズへ縄・鎖・手錠・ストラップを重ねられる「拘束・固定（任意）」と、物理的な競合判定
- 成人キャラクター向け・非流血・非損傷・首拘束なしに限定した拘束プリセット8件
- 鎖だけに接続先・鎖の輪・衣装外の経路を補助し、後ろ手では手指・肘・肩の可視性を強化
- 拘束具の生成難易度目安（縄：安定、手錠・ストラップ：中、鎖：難）と高難度構図のAdvisor誘導
- 画角外の設定を保持したまま、プロンプト出力だけを抑制
- 否定命令を混ぜず、必要な姿勢・見え方を肯定形へまとめたPositive prompt
- 構造化プロンプト、詳細英文、日本語構造一覧と、初期値OFFの任意Negative prompt
- 任意の「文字・記号を抑える」「撮影機材を映さない」「服を保持する」出力補助、四点支持用の白T＋黒ラウンジショーツ補助、背中の開いた服を衣装デザインとして扱うプリセット
- 下書き自動保存、名前付きユーザープリセット（最大20件）
- iOS Safari向けコピーのフォールバック
- 320〜430pxを中心にしたスマートフォンUI、セーフエリア、44pxタップ領域

```text

  ↓

  ├─ compact
  ├─ detailed
  ├─ structureJa
```

## データ追加方法

### 選択肢

該当する `data/*.js` の配列へ、既存項目と同じ形式で追加します。日本語ラベルと英語の短縮・詳細表現を分けてください。

腕動作は、使用する手の本数と見える位置を必ず指定します。

```js
{
  id: "hand_on_hip",
  labelJa: "片手を腰に添える",
  prompt: {
    compact: "hand resting on the hip",
    detailed: "The hand rests naturally on the hip."
  },
  resources: { hands: 1 },
  postures: ["standing", "sitting", "kneeling"],
  zones: ["arms", "hands", "torso"]
}
```

新しいIDを追加したら、`state.js` の正規化対象、`generator.js` の出力ブロック、`tests.js` のデータ整合性テストも確認してください。

### プリセット

`data/presets.js` へ通常の状態patchとして追加します。画面専用の分岐は作りません。追加後は `tests.html` で、hard警告が0件、compact / detailedが空でないことを確認してください。

### 警告ルール

`advisor.js` の `check()` から、次の形式の警告を返します。修正案はUI命令ではなく状態patchにします。

```js
{
  id: "rule_id",
  severity: "hard",
  category: "arms",
  titleJa: "警告タイトル",
  messageJa: "説明",
  relatedPaths: ["pose.arms"],
  resolutions: [
    { labelJa: "修正案", patch: { "pose.arms.combined": null } }
  ]
}
```

自動修正で値を黙って削除しないでください。UI上で利用者が修正案を選んだときだけpatchを適用します。

## 既知の制限

- 画像生成AIによってプロンプトの解釈は異なります。
- 左右は反転する場合があります。厳密な左右指定はMVP対象外です。
- 手指の完全な正確性は保証しません。
- 複雑な手足指定は、論理上の矛盾がなくても崩れる場合があります。
- カメラ・ポーズ指定は、利用するモデルやLoRAに上書きされる場合があります。
- 警告がないことは、画像生成の成功を保証しません。
- 6ステップの詳細設計は一人用です。相手視点はカメラ位置にいる画面外の相手を想定し、二人目の人物は出力しません。二人の構図は「二人のポーズを作る」から、用意した7種を基準に指定します。
- 二人用のSDXL出力は人物ごとにタグを分けられないため、上下・前後を取り違えることがあります。
- 恋愛・BL・会話・対峙などの距離感づくりに使えますが、モデルによっては前景へ相手の身体要素が生成される場合があります。
- 複数人構図、魚眼、ControlNet連携には対応しません。Viewerの手は対応プリセットで片手だけを前景へ表示します。

## 恋人・親しい相手カテゴリについて

このカテゴリは、BL、男女カップル、百合、夢創作、夫婦、親密な日常シーンを含む汎用的な関係性構図です。一人だけを描き、画面外の恋人・親しい相手との関係を、視線・距離・仕草・カメラ高さ・支持状態で表現します。

ベッド、ソファ、歩きながらの距離感、ハート、抱きしめる直前、頬へ触れる仕草に加え、背中・腰・背面衣装を見せる構図も公開向けの中立的な文言で扱います。プリセット画面では「恋人・親しい相手」から、シーンの「背中主役」で該当する5件を絞り込めます。性的・露骨な表現を目的としたツールではありません。

Viewerの手を直接描く半分ハート、手つなぎ、手の甲へのキスなどは「手のやりとり」から選べます。

## 特殊・演出カテゴリについて

特殊・演出は成人キャラクター向けの非流血・非損傷表現です。縄・鎖・手錠・ストラップの対象部位を手首、足首、腕と胴体へ限定し、Positiveでは「首が空いている」「床と脚で体重を支える」「清潔で無傷の皮膚」のような完成状態を肯定形で指定します。

拘束プリセット8件に加え、STEP 3の「拘束・固定（任意）」から既存ポーズへ拘束条件を重ねられます。両手支持、両手ジェスチャー、Viewerとの手のやりとり、椅子の有無、足首固定時の姿勢など、物理的に矛盾する組み合わせはAdvisorが通知します。旧保存データでは拘束機能は自動的に有効になりません。

「特殊・演出」→「特殊ポーズ・運動」から、運動・演出用の身体姿勢8件を選べます。拘束機能は初期OFFです。四股は片脚を上げる前の両足接地の構えとして扱います。支持点を要する7姿勢では、狭い画角を選んでも出力だけ全身へ補正し、Advisorと日本語構造で説明します。保存した画角は変えません。クロップ指定との競合はAdvisorの修正案で解消してください。

## compact短縮について

主ポーズを `arms crossed`、`hand on chin`、`on all fours` などへ短縮し、補助条件と安定化補助を分けています。正面顔・Viewer直視・開眼が一致するときだけ `looking at viewer` へ統合し、横顔や横外しの視線は残します。`contrapposto` は片脚重心・軽い腰ずれ・骨盤と上体の向きが揃う場合だけ使います。

四点支持の支持点・両手両膝の可視性、拘束の部位・固定先・非損傷性、Viewerの片手条件、服保持は残します。自由入力は短縮・分割しません。変更前69件の比較ではcompactが全件短縮され、detailed／日本語構造は全件一致しました。基本15件の文字数短縮率は19〜40%です。文字数での比較であり、モデル固有のトークン数や生成成功率を保証するものではありません。

今回の変更と代表的な全文比較は [改修レポート](CHANGELOG-20260907.md) を参照してください。

実機生成で崩れやすかった鎖は、縄とは別に「見える固定先」「鎖の輪」「身体と衣装の外側を通る経路」を追加します。後ろ手拘束では、腰の後ろの両手首、指、肘の曲がり、肩との自然な接続を明示します。旧公開版と比べた拘束プリセットの構造化Positiveは約25〜31%短縮しています。

Negative promptをONにした場合だけ、血・損傷・手指破綻、鎖の浮遊や貫通、正面化、撮影機材などの除外語を短い別欄へ出します。PositiveはNegativeなしでも構図の意味が成立する設計で、自由入力は否定語を含む場合も原文のまま末尾へ保持します。

## 二人用ポーズと出力先について

二人用は成人キャラクター同士を前提にした、姿勢・向き・手足・接触点・カメラの指定です。露骨な性行為や性器の描写は扱いません。人物Aは動作する側（主導側）、人物Bは受ける側（相手側）で固定しています。

ポーズの意味データ（`data/pair-poses.js`）と出力処理（`pair.js`）は分離しています。出力先ごとに文構造を組み立て、文字列置換で3系統に対応させてはいません。設計と検証結果は [改修レポート（2026-10-27）](CHANGELOG-20261027.md) を参照してください。生成結果の再現性は、実際の生成モデルで別途確認が必要です。

人物A・Bの外見・服装プロンプトの組み合わせ方と、入力の扱いは [改修レポート（2026-10-28）](CHANGELOG-20261028.md) を参照してください。
